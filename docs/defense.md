# Panda Slang: показ проекта и проверка готовности

## Что действительно реализовано

- 200 записей из предоставленного PDF, без дубликатов. Все девять исходных колонок сохранены (номер и восемь содержательных полей); добавлена категория.
- Анализ текста по базе: подсветка фрагментов, варианты через «/», латинские сокращения независимо от регистра, пробелы OCR, некоторые формы без «了», ограниченные шаблоны с X.
- Для одиночных иероглифов нужны границы слова, чтобы «乐» не считалось сленгом внутри «快乐».
- Вайб-чек с двумя зонами и примерами на китайском и русском.
- Поиск по иероглифам, пиньиню без тонов, значению и примерам; 10 категорий; страницы по 24 записи.
- Избранное, история до 20 разборов, скачивание разбора, карточки и мини-тест.
- OCR: Tesseract.js на устройстве посетителя, китайская и английская модели с того же сайта; обработка ошибок, лимит 8 МБ и отмена.
- Мобильная навигация, диалоги с управлением фокусом и Escape, метки доступности, настройка уменьшенной анимации.

## Сценарий демонстрации (3–4 минуты)

1. На главной выбрать пример «Работа и учёба». Показать 内卷, 躺平 и 摸鱼, кликнуть подсвеченное слово, открыть зелёную и красную зоны.
2. Выбрать «Реакция в чате»: показать, что YYDS распознаётся при вводе заглавными буквами.
3. Открыть словарь, ввести neijuan без тонов. Сохранить слово звёздочкой. Показать его в «Избранном».
4. Ввести «这是一本书。» в разбор: объяснить, что отсутствие совпадений не выдаётся за доказательство отсутствия сленга, и сайт не придумывает перевод.
5. Загрузить чёткий PNG/JPG со сленгом. Дождаться загрузки моделей, проверить распознанный текст, запустить разбор. Заранее выполнить первый запуск OCR перед показом.
6. Открыть практику, показать карточку и мини-тест. Объяснить, что прогресс хранится на устройстве.
7. В словаре скачать JSON: показать 200 полных записей.

## Что нельзя заявлять без дополнительных работ

- Это бесплатная словарная версия, а не интеграция с LLM API. Выбранная пользователем версия сознательно не использует платную генерацию.
- Лингвистическая проверка таблицы не выполнялась разработчиком. Согласовать содержание с лингвистом команды.
- 90% точности, UX ≥ 4,5/5 и скорость OCR < 5 с не подтверждены: нужны реальные измерения и бета-тест. Время на экране — только время словарного поиска, не загрузки и распознавания.
- Нет общей базы отзывов или аккаунтов посетителей. Избранное и прогресс не синхронизируются между браузерами.
- Приватная публикация не равна доступу всем тестировщикам. Перед тестированием владелец должен отдельно выбрать нужную аудиторию.

## Как провести бета-тест

Собрать 20 участников и 100 скриншотов. Для каждого отметить исходный текст, правильность OCR, найденные выражения, корректность смысла и уместности (оценка лингвиста), полное время от отправки до результата. Отдельно записать время первого запуска с загрузкой моделей и повторного запуска. После задач попросить оценить удобство от 1 до 5. Отчёт заполнять только по фактическим данным.

## Проверки кода

npm run typecheck
npm test
npm run build

Автотесты проверяют целостность 200 записей, распознавание всех заголовков и вариантов, регистр, пробелы OCR, границы сокращений, пересечения, шаблоны и поиск по пиньиню. Они не заменяют лингвистическую оценку и проверку интерфейса на реальных устройствах.
